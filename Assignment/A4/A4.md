## 4. Prompt 格式要求

`run_sft.py` 中的 `format_input(entry)` 已给出基本格式。每条样本应拼成：

```text
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
{instruction}

### Input:
{input}
```

如果 `entry["input"]` 为空，则不要追加 `### Input:` 部分。

训练时完整文本还需要继续拼接 response：

```text

### Response:
{output}
```

也就是说，完整训练样本为：

```text
{instruction_plus_input}

### Response:
{output}
```

### 5.3 实现 `init_data_loaders`

函数职责：

- 按 85%/10%/5% 切出 train/test/val。
- 分别构造 dataset：
  - `train_dataset = dataset_class(train_data, tokenizer)`
  - `test_dataset = dataset_class(test_data, tokenizer)`
  - `val_dataset = dataset_class(val_data, tokenizer)`
- 用 `DataLoader` 包装：
  - train loader 建议 `shuffle=True`。
  - test/val loader 可 `shuffle=False`。
  - 使用传入的 `batch_size` 和 `collate_fn`。

当前代码里要特别注意：`init_data_loaders` 的函数签名是：

```python
def init_data_loaders(data, tokenizer, batch_size, dataset_class, collate_fn):
```

但 `main` 里目前调用少传了 `batch_size`：

```python
train_loader, test_loader, val_loader = init_data_loaders(data, tokenizer, CustomDataset, customized_collate_fn)
```

应改成类似：

```python
train_loader, test_loader, val_loader = init_data_loaders(
    data, tokenizer, batch_size, CustomDataset, customized_collate_fn
)
```

同时 `batch_size` 最好在创建 data loader 前定义。

### 5.4 实现 `InstructionDataset`

non-masking 版本只需保存完整 token 序列：

1. 调用 `format_input(entry)` 得到 instruction + input。
2. 拼接 `response_text = f"\n\n### Response:\n{entry['output']}"`。
3. 得到 `full_text = instruction_plus_input + response_text`。
4. 用 GPT-2 tokenizer 编码，并 append 到 `self.encoded_texts`。

使用的是：

```python
tokenizer = tiktoken.get_encoding("gpt2")
```

### 5.5 实现 `custom_collate_fn`

non-masking 的 collate 需要：

- 对 batch 内每条 token 序列 pad 到同一长度。
- 一般会额外补一个 `pad_token_id=50256`，保证 input/target shift 后长度一致。
- `inputs = padded[:-1]`
- `targets = padded[1:]`
- targets 中 padding token 位置应改成 `ignore_index=-100`，使 loss 不计算 padding。
- 允许用 `allowed_max_length=1024` 截断。
- 最后 `torch.stack` 成 batch tensor，并转到 `device`。

### 5.6 实现 `train_model`

训练循环结构类似之前 pretraining assignment 的 `train_model_simple`，但参数更少。

需要做的事情：

- 对每个 epoch：
  - `model.train()`
  - 遍历 `train_loader`
  - 前向得到 logits。
  - 用 `torch.nn.functional.cross_entropy` 或等价方法计算 next-token prediction loss。
  - `optimizer.zero_grad()`
  - `loss.backward()`
  - `optimizer.step()`
- 每个 epoch 或固定 interval 计算验证集 loss：
  - `model.eval()`
  - `torch.no_grad()`
  - 遍历 `val_loader`
- 返回：
  - `train_losses`
  - `val_losses`

这些 loss 后续要用于绘制曲线。

## 6. Requirement 2：Mask 掉 instruction 和 input 部分（10 分）

这一部分要求实现 masking 条件下的 SFT。核心思想是：训练时 prompt 部分只作为上下文，不对 instruction 和 input 的 token 计算 loss，只对 response 部分计算 loss。

### 6.1 实现 `InstructionDatasetMask`

新类需要有两个成员：

- `self.encoded_texts`：完整文本 token IDs。
- `self.instruction_lengths`：`instruction_plus_input` 的 token 长度。

每条样本处理方式：

1. `instruction_plus_input = format_input(entry)`
2. `response_text = f"\n\n### Response:\n{entry['output']}"`
3. `full_text = instruction_plus_input + response_text`
4. 保存完整文本 token。
5. 单独计算 instruction/input 部分长度：

```python
instruction_length = len(tokenizer.encode(instruction_plus_input))
```

`__getitem__` 需要返回：

```python
return self.instruction_lengths[index], self.encoded_texts[index]
```

### 6.2 实现 `custom_collcate_fn_mask`

注意代码中的函数名拼写是 `custom_collcate_fn_mask`，少了一个 `l`，但 `main` 里也是按这个名字调用的，所以可以保持一致。

它和普通 `custom_collate_fn` 的主要区别：

- batch item 不再只是 token list，而是 `(instruction_length, encoded_text)`。
- 得到 `inputs` 和 `targets` 后，需要把 targets 中 instruction/input 对应位置设成 `ignore_index=-100`。
- padding 对应位置同样也要设为 `ignore_index=-100`。

由于 targets 是右移一位后的序列，mask 长度需要小心对齐。目标是让模型不因为 prompt token 被监督，只监督 response token。

### 6.3 命令行开关

代码中已经预留参数：

```bash
--mask_instructions 0
--mask_instructions 1
```

- `0`：non-masking，instruction/input/response 都参与 next-token loss。
- `1`：masking，instruction/input 不参与 loss，主要训练 response。

### 6.4 保存模型


## 7. Requirement 3：生成回答并用 LLM-as-a-judge 评测（10 分）

### 7.1 实现 `generate`

`generate(model, input_ids, max_new_tokens=256)` 要实现 greedy decoding：

- 输入为 instruction + input 的 token IDs。
- 每一步：
  - 前向得到 logits。
  - 取最后一个位置的 logits。
  - `argmax` 得到下一个 token。
  - 拼接到当前序列末尾。
- 不需要 random sampling。
- KV-cache 是 optional，不要求实现。
- 生成到 `max_new_tokens` 或遇到合适停止条件即可。

### 7.2 生成测试集 responses JSON

代码中已经预留参数：

```bash
--generate_responses 0
--generate_responses 1
```

当开启生成时，应对 test split 的 110 条样本生成回答，并保存 JSON。

每条输出必须包含下面四个 key，名字必须完全一致，因为评测脚本依赖这些字段：

```json
{
  "instruction": "Name the author of 'Pride and Prejudice'.",
  "input": "",
  "output": "Jane Austen.",
  "model_response": "The author of 'Pride and Prejudice' is Jane Austen."
}
```

重点：

- `instruction`、`input`、`output` 来自原测试集样本。
- `model_response` 是模型生成的文本。
- 输出 JSON 应该有 110 entries。
- 建议分别保存：
  - `responses_355M_mask0.json`
  - `responses_355M_mask1.json`
